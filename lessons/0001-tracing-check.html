class IpInterfaceBrief:
    """Interface facts parsed from `show ip interface brief` output."""

    command: str = "show ip interface brief"

    def __init__(self, hostname: str, raw_output: str) -> None:
        self.hostname = hostname
        self.raw_output = raw_output
        self.interfaces: dict[str, dict[str, str]] = {}

    def gather(self) -> dict[str, dict[str, str]]:
        for line in self.raw_output.splitlines():
            if self.is_data_row(line):
                name, attrs = self.parse_row(line)
                self.interfaces[name] = attrs
        return self.interfaces

    def is_data_row(self, line: str) -> bool:
        return bool(line.strip()) and not line.startswith("Interface")

    def parse_row(self, line: str) -> tuple[str, dict[str, str]]:
        fields = line.split()
        return fields[0], {"ip": fields[1], "protocol": fields[-1]}


class IosIpInterfaceBrief(IpInterfaceBrief):
    network_os: str = "cisco.ios.ios"


class NxosIpInterfaceBrief(IpInterfaceBrief):
    network_os: str = "cisco.nxos.nxos"

    def is_data_row(self, line: str) -> bool:
        is_row = super().is_data_row(line)
        return is_row and not line.startswith("IP Interface Status")

    def parse_row(self, line: str) -> tuple[str, dict[str, str]]:
        name, attrs = super().parse_row(line)
        # NX-OS packs three states in one column: protocol-up/link-up/admin-up
        protocol_state = attrs["protocol"].split("/")[0]
        attrs["protocol"] = protocol_state.removeprefix("protocol-")
        return name, attrs

Why this lesson

LR-0003 says you can trace short teaching classes, but the drills were never recorded, so the claim is self-reported. Before building on it, I want evidence. Everything here uses constructs that LR-0003 lists as covered: class and instance attributes, overrides, self.method() dispatch, super(). If you trace this cleanly, we move straight to writing classes. If you don't, we know exactly where to start.

The class does the job a resource module's facts class does: it turns captured show output into structured data. The real cisco.ios VlansFacts does it for show vlan. That class is much bigger and doesn't use inheritance, so today's code is a stand-in, not a model of it.

What the code models

  • The real object: one device's show ip interface brief output, and the interface facts parsed from it.
  • Initializer arguments: hostname names the device; raw_output is the captured CLI text. No connection, no device: the text is passed in directly.
  • Instance state: interfaces, a dict from interface name to {"ip": …, "protocol": …}, filled in by gather().
  • Methods: gather walks the output line by line; is_data_row decides whether a line is an interface row; parse_row turns one row into a name and its attributes.
  • Why two subclasses: each platform gets a network_os name (the value you'd put in ansible_network_os). NX-OS also prints a VRF banner line above the header, and it packs three states into its last column.

Synthetic device output. RAW_IOS and RAW_NXOS are typed from memory to look like each platform's output. They aren't captures. If your Nexus prints something different, tell me. It won't change the answers here, because the code only sees these strings.
