How methods get self

r1.show_version() is two steps. Reading r1.show_version gives you a bound method, which refers to the function and r1. The () then calls the function with r1 as its first argument. That explains an error that counts an argument you never wrote.

A puzzle to start with

r1: show version

    print(r1.save_command())
          ^^^^^^^^^^^^^^^^^
TypeError: IosRouter.save_command() takes 0 positional arguments but 1 was given

Read the last line closely. A positional argument is an argument matched to a parameter by its position: the first argument goes to the first parameter, and so on. save_command's def line has no parameters, so it “takes 0”. But the brackets in r1.save_command() are empty, and Python says 1 was given. Where did that argument come from?

Two steps hiding in one line

A call like r1.show_version() is really two operations, and you can split them apart:

m = r1.show_version     # 1. read the attribute (no brackets)
m()                     # 2. call what you got

Step 1, the read. This is lesson 0003's attribute lookup: not on r1, found on the class IosRouter. What's found there is the function the def line made. But Python doesn't hand you that plain function. Because a function stored on the class was read through an instance, Python builds a new object, a bound method, which refers to two objects:

  • the function, found on the class;
  • the instance that came before the dot, here r1.

So two objects are in play, and only one of them is the method you wrote. The method is the function the def line made: made once, stored on the class. The bound method is a separate object, made each time you read the method through an instance. It doesn't contain the function or a copy of it; it refers to it, the way a name does. Python's own labels show the difference: type(IosRouter.show_version) is function, and type(r1.show_version) is method. (Yes, Python's type name for the bound method is method. This course always says bound method for it, to keep the two apart.)

Step 2, the call. Calling the bound method calls the function, with the instance put in front of whatever arguments you wrote. So m() calls the function with one argument, r1, and that argument lands in the first parameter, self.

Python tutorial, §9.3.4 Method Objects: “references to both the instance object and the function object are packed into a method object. When the method object is called with an argument list, a new argument list is constructed from the instance object and the argument list, and the function object is called with this new argument list.” (The tutorial says method object; Python prints bound method, and so does this course.)

In dict-and-function terms, it's like packing a function and a device dict together, then calling one with the other. A simplified model, not Python's actual code:

def show_version(device: dict) -> str:
    return f"{device['hostname']}: show version"


r1 = {"hostname": "r1"}
bound = {"function": show_version, "instance": r1}   # step 1: the read
bound["function"](bound["instance"])                  # step 2: the call

Back to the puzzle

Take r1.save_command() one step at a time:

  1. The read: save_command isn't on r1; it's found on IosRouter. Python returns a bound method that refers to that function and r1.
  2. The call: you wrote no arguments, so the argument list is just r1. That's one positional argument.
  3. The function's def line, def save_command():, has no parameter to receive it. Python raises the TypeError.

The fix is def save_command(self):. Note what that fix is not. self isn't a keyword, and Python never looks for that name. It puts the instance into the first parameter, whatever that parameter is called. Calling it self is a convention (the tutorial, §9.4: “nothing more than a convention: the name self has absolutely no special meaning to Python”). Keep to the convention; every Python reader expects it. If the first parameter is missing, the instance has nowhere to go.

Read through the class: nothing is bound

Lesson 0001 showed that r1.show_version() is the same call as IosRouter.show_version(r1). Now you can see why both work. Reading IosRouter.show_version goes straight to the class, with no instance before the dot, so there's nothing to bind. You get the plain function, and you pass the instance yourself.

ExpressionWhat you get
r1.show_versionA bound method: the function plus r1. Nothing has run yet.
r1.show_version()The function called with r1 as its first argument.
IosRouter.show_versionThe plain function. No instance.
IosRouter.show_version(r1)The same call as r1.show_version(), with the instance passed by hand.

Why it's designed this way. Lesson 0001's procedural version was one function, describe(device), that you called with whichever device dict you wanted. A class keeps one function on the class for every instance. The bound method is how that one shared function learns which device to work on: the instance before the dot is passed in for you. It's the same pattern as before; Python fills in the first argument.

See it in Python

Don't take this page's word for it. Run python3 -i lessons/code/l0004_demo.py. The -i drops you into the REPL after the file runs, with IosRouter and r1 already defined. The file's own TypeError prints first; ignore it. Then type each line after >>>. This is what it printed when this lesson was written (your addresses after 0x will differ):

>>> IosRouter.show_version             # read through the class

>>> IosRouter.show_version(r1)         # pass the instance yourself

Read the first printout from the inside out: a bound method; its function is IosRouter.show_version; the instance it refers to is “an IosRouter object at 0x…”, which is r1. The last error is the puzzle's mirror image: there, one argument too many; here, one too few.

Storing a bound method and calling it later: the tutorial, §9.3.4: “x.f is a method object, and can be stored away and called at a later time.”

Under the hood (layer 3, optional)

Skip this if the two steps above aren't solid yet. It adds no new behaviour, only how step 1 knows to build a bound method.

  • Functions are descriptors. A descriptor is an object with a __get__ method. When lookup finds an attribute on the class and that object has __get__, Python calls it and returns whatever it returns. A function's __get__ builds the bound method. So r1.show_version does, in effect, IosRouter.__dict__["show_version"].__get__(r1, IosRouter). Type that line and you get the same bound method printout.
  • The two references have names: m.__func__ is the function and m.__self__ is the instance. m.__self__ is r1 is True.
  • Each read builds a new bound method. r1.show_version is r1.show_version is False: two reads, two objects. == is True, because both refer to the same function and the same instance.
  • Only functions found on the class get bound. A function stored on an instance, sw1.show_clock = show_clock, comes back from lookup as the plain function, because the descriptor step applies only to what's found on the class. Then sw1.show_clock() fails with “missing 1 required positional argument”. This is also why lesson 0003's Q5 string, stored on the instance, simply hid the method.

Source: the Descriptor HowTo Guide, Functions and methods: “functions are non-data descriptors that return bound methods during dotted lookup from an instance.” Written for experienced programmers; the section's MethodType class is the dict model above, done properly.

Your turn: a switch that never comes into line

The reconciliation rule this class follows is add-only, like Ansible's merged state but for VLAN IDs only: wanted VLANs the switch lacks get created, and VLANs on the switch that aren't in WANT are left alone. Under overridden they would be removed (resource module states; the ios_vlans overridden example sends no vlan 10 for a VLAN not listed).

Open lessons/code/l0004_switch.py from the Explorer sidebar:

class IosSwitch:
    """One IOS access switch, reconciled add-only.

    Like Ansible's merged state, for VLAN IDs only: wanted VLANs the
    switch lacks get created; VLANs not in WANT are left alone.
    """

    def __init__(
        self, hostname: str, have_vlans: list[int], want_vlans: list[int]
    ) -> None:
        self.hostname = hostname
        self.have_vlans = have_vlans
        self.want_vlans = want_vlans

    def missing_vlans(self) -> list[int]:
        """The wanted VLAN IDs that the switch doesn't have yet."""
        return [
            vlan_id for vlan_id in self.want_vlans
            if vlan_id not in self.have_vlans
        ]

    def needs_change(self) -> bool:
        return len(self.missing_vlans()) > 0


def plan_push(switch: IosSwitch) -> list[str]:
    """The lines to send to one switch; empty if it has every wanted VLAN."""
    if switch.needs_change:
        lines = [f"vlan {vlan_id}" for vlan_id in switch.missing_vlans()]
        return lines + ["end", "write memory"]
    return []


if __name__ == "__main__":
    sw1 = IosSwitch("sw1", have_vlans=[1, 10], want_vlans=[10, 20])
    sw2 = IosSwitch("sw2", have_vlans=[1, 10, 20], want_vlans=[10, 20])
    print("sw1:", plan_push(sw1))
    print("sw2:", plan_push(sw2))

missing_vlans uses a list comprehension, which no earlier lesson taught. It's the same as this loop, with the append part written first (tutorial §5.1.3; glossary):

missing = []
for vlan_id in self.want_vlans:          # binds vlan_id to each item in turn
    if vlan_id not in self.have_vlans:   # tests it
        missing.append(vlan_id)          # the leading vlan_id: what's kept
return missing

Only want_vlans is looped over; have_vlans is only searched. The name vlan_id is local to the comprehension and is gone after the closing ]; the new list keeps references to the objects, not to the name.
