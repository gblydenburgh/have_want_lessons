Names and objects

What assignment does, mutating vs rebinding, and the Perl you already know.

The rules

  1. Names refer to objects. A name (variable, attribute, parameter) never contains an object; it refers to one.
  2. Assignment makes the name on the left refer to the object on the right.
  3. Assignment never copies. want = have gives one object, two names.
  4. Mutating an object is seen through every name that refers to it.
  5. Rebinding a name moves only that name. Other names, and the old object, are untouched.
  6. Passing an argument is assignment: the parameter refers to the caller's object.
  7. A separate object must be built on purpose. No assignment gives you one.

Mutate or rebind?

HAVE and WANT

  • Build WANT as a new dict; never change the HAVE dict to get it.
  • If WANT and HAVE are one object, every comparison finds nothing to do, and the module silently reports no change.
  • netcommon's dict_merge(base, other) “Return[s] a new dict object”.

Check in the REPL

>>> want is have      # one object?
>>> want == have      # same contents?
>>> d.hostname is name   # attributes refer to objects too
