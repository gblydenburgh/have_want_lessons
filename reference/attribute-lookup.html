Attribute lookup

Where instance.attr is found, where instance.attr = … goes, and what belongs on the class.

The rules

  1. Reading instance.attr looks it up: the instance first, then its class. On neither: AttributeError.
  2. Writing instance.attr = value never searches. It stores attr on the instance itself, never on the class.
  3. An instance attribute hides a class attribute with the same name, for that instance only.
  4. instance.attr.append(…) is a read, then a mutation. If the read found a class attribute, the one shared object changes for every instance.
  5. Methods use the same lookup. Data stored on an instance under a method's name hides the method.

Read, write, or both?

LineWhat Python does
x = sw1.commandsRead: the instance, then the class.
sw1.commands = []Write: stored on sw1.
sw1.commands.append(…)Read, then mutate the object found.
self.x = self.x + [v]Read (may find the class's), build a new list, write it to the instance.
del sw1.commandsDelete from sw1; lookup reaches the class again.

Never mutate a class attribute through self.

Check it in Python

vars(r1)                          # r1's own attributes only
"commands" in vars(ConfigPush)    # stored on the class?
r1.commands is ConfigPush.commands   # found on the class by lookup?
r1.commands is sw1.commands       # two instances sharing one object?

Layer 3. vars(r1) returns r1.__dict__. Reading checks r1.__dict__, then type(r1).__dict__; writing does r1.__dict__["name"] = value. A class's __dict__ is read-only (mappingproxy): assign Cls.x = … instead. Incomplete until later lessons: parent classes (inheritance), property (checked before the instance). How a method found on the class becomes a bound method: see bound methods.
