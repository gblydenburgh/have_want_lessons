Class anatomy

The parts of a class, what each is called, and the dict-and-functions code it replaces.

The parts

class Device:                                         # the CLASS (the blueprint)
    def __init__(self, hostname, mgmt_ip, platform):  # the INITIALIZER; runs on each new instance
        self.hostname = hostname                      # stores an ATTRIBUTE on the instance
        self.mgmt_ip = mgmt_ip
        self.platform = platform

    def describe(self):                               # a METHOD; self = the instance it works on
        return f"{self.hostname} ({self.platform}) at {self.mgmt_ip}"


r1 = Device("r1", "10.0.0.1", "ios")                  # INSTANTIATE: creates an INSTANCE, runs __init__
print(r1.hostname)                                    # read an attribute: 'r1'
print(r1.describe())                                  # call a method; same as Device.describe(r1)

Rules to remember

  • r1.describe() is exactly Device.describe(r1) (tutorial §9.3.4).
  • self is only a naming convention for the first parameter (§9.4).
  • __init__ runs once per Device(...) call, after the new instance exists (data model). Tutorials often call it the constructor.
  • Each instance has its own attributes. Creating sw1 doesn't change r1.
  • A parameter (mgmt_ip) is a local name for the argument; self.mgmt_ip = mgmt_ip is what stores it on the instance.
  • When a dict and a few functions do the job, keep them. Use a class when data and the functions that belong to it should travel together.
