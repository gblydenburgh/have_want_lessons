OOP glossary

The terms the lessons use, in plain words.

Each entry gives the meaning in plain words and, in italics, a common wrong version to avoid. Terms are added here as lessons teach them. Primary source: the Python tutorial, Classes.

The basics

class
A definition, a blueprint: it says what data each instance holds and which methods work on it. Device is a class. A class is not an instance created from it: Device isn't a device.
instance (object)
One particular thing built from a class. r1 = Device("r1", ...) makes r1 an instance of Device. Each instance has its own attribute values. Not “instantiated class” or “instanced class”.
instantiate
Create an instance by calling the class: Device(...). The instance is the result.
attribute
A named value stored on an instance, read with a dot: r1.hostname. Like a dict key, written differently.
method
A function defined inside a class, which works on one instance at a time: describe. Called as r1.describe().
self
The first parameter of a method: the instance the method is working on. In r1.describe(), self is r1, because the call is the same as Device.describe(r1). (§9.3.4) Not the class, not the initializer, not “all of the class”.
initializer (__init__)
The method Python runs automatically on each new instance, to store its starting attributes. It runs once per Device(...) call. Often called the “constructor”, but the instance already exists when it runs (data model).
parameter vs attribute
In def __init__(self, mgmt_ip), mgmt_ip is a parameter: a local name that exists only during the call. self.mgmt_ip = mgmt_ip stores its value as an attribute, which stays on the instance.

Reconciliation and Ansible

HAVE / WANT
HAVE is observed device state; WANT is intended input. Don't normalize valid HAVE to make a test pass.
state (merged, replaced, overridden, deleted)
Ansible calls these state values, but each is a reconciliation policy: a rule for combining HAVE and WANT. (user guide) Not the resulting device state.
