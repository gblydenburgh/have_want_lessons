OOP glossary

The terms every lesson uses, and the wrong versions they replace.

Each entry gives the precise meaning and, in italics, the slip it replaces. The slips are the ones in LR-0006: each one hides a wrong mental model, not just wrong wording. Primary source: the Python tutorial, Classes.

Objects

class
The object a class statement creates. It holds the attributes and methods its instances share. NxosIpInterfaceBrief is a class. A class definition is not an instance created from it.
instance (of a class)
An object created by calling the class: nx = NxosIpInterfaceBrief(...) makes nx an instance of NxosIpInterfaceBrief. Not “instantiated class” or “instanced class”.
instantiate
The action of creating an instance by calling the class. The instance is the result.
self
The particular instance the method is running on. In nx.gather(), self is nx. Not the class, not the initializer, not “all of the class”.

Attributes and names

instance attribute
Stored on one instance, usually set as self.name = …; it appears in that instance's __dict__. (§9.3.5)
class attribute
Defined in the class body, shared by every instance and found through lookup; it is not in the instance's __dict__. Not the same as an instance attribute, even when accessed as self.x.
method-local variable
A bare name assigned inside a method (fields = …). It disappears when the call returns, unless the object it refers to is kept somewhere else. Not an instance attribute.

Inheritance and lookup

override
A subclass defines a method (or attribute) with the same name as one in a base class; lookup finds the subclass's version first. (§9.5)
method lookup, MRO
Python searches the instance, then the classes in the method resolution order (type(obj).__mro__), and stops at the first match. Not “searching outside the instanced class” or “going to the parent”.
defining class vs operating instance
For an inherited method, the class that defines it is where the code lives; the instance it operates on is self. They are different things.
super()
Continues the lookup in the MRO after the current class, on the same instance. (docs) It doesn't create or refer to a separate parent object.

Reconciliation and Ansible

HAVE / WANT
HAVE is observed device state; WANT is intended input. Don't normalize valid HAVE to make a test pass.
state (merged, replaced, overridden, deleted)
Ansible calls these state values, but each is a reconciliation policy: a rule for combining HAVE and WANT. (user guide) Not the resulting device state.
collections.Counter
A class (a dict subclass). Usually the right move is to use an instance of it, not define a new class.
