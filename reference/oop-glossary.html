OOP glossary

The terms the lessons use, in plain words.

Each entry gives the meaning in plain words and, in italics, a common wrong version to avoid. Terms are added here as lessons teach them. Primary source: Think Python, 3rd edition, chapters 14–17.

The basics

class
A definition, a blueprint: it says what data each instance holds and which methods work on it. Device is a class. A class is not an instance created from it: Device isn't a device.
instance
One particular thing built from a class. r1 = Device("r1", ...) makes r1 an instance of Device. Each instance has its own attribute values. Every instance is an object; saying “instance” adds which class it came from, so it's always “an instance of …”. Every Python object is an instance of some class: "r1" is an instance of str. Not “instantiated class” or “instanced class”.
instantiate
Create an instance by calling the class: Device(...). The instance is the result.
attribute
A named value read with a dot: r1.hostname. Like a dict key, written differently. It's stored either on the instance or on its class (see the next section). Like any name, it refers to an object: after self.hostname = hostname, the attribute and the parameter refer to the same string. Not a copy of the value.
method
A function defined inside a class, which works on one instance at a time: describe. Called as r1.describe().
self
The first parameter of a method: the instance the method is working on. In r1.describe(), self is r1, because the call is the same as Device.describe(r1). (§9.3.4) Not the class, not the initializer, not “all of the class”.
initializer (__init__)
The method Python runs automatically on each new instance, to store its starting attributes. It runs once per Device(...) call. Often called the “constructor”, but Python has already created the instance when it runs; it only fills it in. Think Python calls it “the init method”.
parameter
The name in a def line that receives a value: in def describe(device), device.
argument
The value passed in when a function or method is called: in describe(r1), r1.
local variable
A name that exists only while a function or method runs, including its parameters. It's gone when the function returns. Not an attribute: in __init__, the parameter mgmt_ip disappears, while self.mgmt_ip = mgmt_ip makes an attribute on the instance refer to the same object, and the attribute stays.
expression
Code that produces a value: have == expected, "r1", merge_want(have, overrides). Any expression can be put in parentheses without changing its value. A comma inside the parentheses makes a tuple: ("r1", "sw1").
statement
An instruction Python carries out: an assignment, if, def, return, assert. assert <condition>, <message> is a statement made of two expressions. Not a function: the assert's message isn't an argument.

Names and objects

From lesson 0002. Primary source: Ned Batchelder, Facts and Myths about Python names and values.

object
Any value Python has created: a dict, a list, a string, a number, a Device instance.
type
The class an object is an instance of. type(obj) returns it: type(sw1) is Switch, type(sw1.hostname) is str. It decides what you can do with the object, such as which methods it has. (data model §3.1: “Every object has an identity, a type and a value.”) A name has no type of its own: the type belongs to the object it refers to.
name (variable)
A label that refers to an object: have, r1. Parameters and attributes are names too. A name doesn't contain or own its object, and an object doesn't know its names.
refer to / reference
A name refers to an object; the link is a reference. Python follows it automatically every time the name is used, so there's no @{} or ->.
assignment
name = expression makes the name refer to the object on the right (the Python reference: the name is “bound” to the object). Never a copy: want = have makes no new dict.
aliased / alias
An object is aliased when two or more names refer to it; each name is an alias. A change to the object is seen through all of them.
mutate
Change an object itself: want["name"] = …, .update(), .append(), r1.mgmt_ip = ….
rebind
Make a name refer to a different object: want = {...}. Only that name changes. Doesn't change the object the name referred to before.
equal (==) / identical (is)
Equal: same contents. Identical: the same object. Two separately built dicts with the same keys and values are equal but not identical. Think Python says “equivalent” for equal.

Attribute lookup

From lesson 0003. Primary source: Python tutorial §9.3.5.

instance attribute
An attribute stored on one instance, usually by self.x = … in __init__: hostname. What vars(r1) shows.
class attribute
An attribute stored on the class, by an assignment in the class body outside any def: max_vlan_id = 4094. It's one object, shared by every instance. Methods are class attributes too. The Python tutorial and Think Python say class variable for the data kind. Not copied onto each instance when it's created.
attribute lookup
How Python finds the object for a read of instance.attr: the instance first, then its class, else AttributeError. Methods are found the same way. (data model §3.2.11) Assignment, instance.attr = …, doesn't look anything up: it always stores on the instance itself.

Reconciliation and Ansible

HAVE / WANT
HAVE is observed device state; WANT is intended input. Don't normalize valid HAVE to make a test pass.
state (merged, replaced, overridden, deleted)
Ansible calls these state values, but each is a reconciliation policy: a rule for combining HAVE and WANT. (user guide) Not the resulting device state.
